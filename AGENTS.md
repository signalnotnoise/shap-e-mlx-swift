## Identity and scope

Products, from `Package.swift:12-19`:

- `ShapERuntime`, library. `import ShapERuntime`.
- `ShapECLI`, executable.

Platforms in `Package.swift:6-9`: macOS 14, iOS 17, visionOS 1. CI builds and tests macOS only (`.github/workflows/ci.yml:16-48`). iOS and visionOS are not built in this repository's CI.

Public entry points, `Sources/ShapERuntime/ShapERuntime.swift`:

- `init(modelBundleURL:bpeVocabularyURL:)` at `ShapERuntime.swift:104`.
- `generate(prompt:guidanceScale:numInferenceSteps:sigmaMin:sigmaMax:gridSize:queryBatchSize:seed:)` at `ShapERuntime.swift:209-237` returns one `ShapEMeshResult`. Defaults include `guidanceScale` 15, `numInferenceSteps` 64, `gridSize` 128, `queryBatchSize` 65536, `seed` 0. This overload forces CPU marching cubes (`useMetalMarchingCubes: false` at `ShapERuntime.swift:229`).
- `generate(prompt:batchSize:...)` at `ShapERuntime.swift:248-261` returns `[ShapEMeshResult]`.
- `generate(image: CGImage, ...)` at `ShapERuntime.swift:401-414` returns `[ShapEMeshResult]`. Image guidance default is 3.
- `generate(image: MLXArray, ...)` at `ShapERuntime.swift:436-448`. The comment on that line says the array is expected `[1, 224, 224, 3]` normalized.

`ShapEMeshResult.verticesArray()` is `[Float]` of length `V * 3`. `facesArray()` is `[Int32]` of length `F * 3` (`ShapERuntime.swift:29-36`).

Tensor shapes that the code states:

- CLIP image preprocess: `[1, 224, 224, 3]` float32 (`ImageProcessor.swift:21-26`).
- CLIP text embedding: `[batch, textProjectionDim]` (`ClipTextEmbedder.swift:247-249`). `textProjectionDim` is `text_projection.shape[1]` (`ClipTextEmbedder.swift:107`).
- Text300M `predict`: latent `[B, inputChannels, T]`, timesteps `[B]`, CLIP `[B, clipFeatureDim]`, output `[B, outputChannels, T]` (`Text300MTransformer.swift:356-362`).
- Decoder projection input: latent `[B, D]` (`DecoderParamsProjector.swift:174-175`).
- Marching cubes: SDF `[X, Y, Z]` to verts `[V, 3]` and faces `[F, 3]` (`MarchingCubes.swift:18-23`).

`nCtx` and `dLatent` are manifest metadata (`RuntimeArtifactBundle.swift:133-138`). This repository does not hardcode the production latent width. The stub fixture README compares a real bundle (width 1024, 24 layers, 16 heads, 1024 timesteps) with the checked-in stub (`Tests/ShapERuntimeTests/Fixtures/README.md:28-35`). Those real-bundle numbers are not constants in the transformer. `Text300MTransformer`'s convenience init defaults `nHeads` to 16 and infers the other fields from weight shapes (`Text300MTransformer.swift:180-185`).

## Out of scope

- TripoSR, and any unified wrapper that selects between Shap-E and TripoSR. Those are not in this package.
- Python training, checkpoint conversion, and the upstream export module. This repo only downloads and reads a runtime bundle.
- Mesh extraction is in scope. Shap-E's CPU and Metal marching cubes and OBJ export live here (`MarchingCubes.swift`, `MetalMarchingCubes.swift`, `MeshExport.swift`).

## Build and test

Do not use `swift build` or `swift test`. `run_tests.sh:1-7` says a plain `swift test` can miss MLX's `default.metallib`. The package also compiles `MarchingCubes.metal` (`Package.swift:31`).

Scheme `ShapERuntime-Package` is the name in `run_tests.sh:17-20` and `.github/workflows/ci.yml:45`. `run_tests.sh:18-19` says that autogenerated package scheme is the one configured for tests, and the product scheme is not. This checkout was not listed with `xcodebuild -list` on the machine that wrote these docs (Linux, no Xcode).

Build the executable:

```bash
xcodebuild build \
  -scheme ShapECLI \
  -destination 'platform=macOS' \
  -skipPackagePluginValidation \
  CODE_SIGNING_ALLOWED=NO
```

Test:

```bash
xcodebuild test \
  -scheme ShapERuntime-Package \
  -destination 'platform=macOS' \
  -skipPackagePluginValidation \
  -parallel-testing-enabled NO \
  CODE_SIGNING_ALLOWED=NO
```

The checked-in workflow uses the same scheme and destination, and also passes `-skipMacroValidation` (`.github/workflows/ci.yml:42-49`). It does not pass `-parallel-testing-enabled NO`.

Optional real-weight tokenizer tests read `SHAP_E_BPE` and `SHAP_E_BUNDLE` (`ClipSimpleTokenizerTests.swift:11-18`). `xcodebuild` forwards environment variables that start with `TEST_RUNNER_` into the test process. Pass `TEST_RUNNER_SHAP_E_BPE` and `TEST_RUNNER_SHAP_E_BUNDLE`. The test source does not read the `TEST_RUNNER_` names itself.

```bash
TEST_RUNNER_SHAP_E_BPE=/path/to/bpe_simple_vocab_16e6.txt.gz \
TEST_RUNNER_SHAP_E_BUNDLE=/path/to/runtime_bundle \
xcodebuild test \
  -scheme ShapERuntime-Package \
  -destination 'platform=macOS' \
  -skipPackagePluginValidation \
  -parallel-testing-enabled NO \
  CODE_SIGNING_ALLOWED=NO
```

`scripts/fetch_weights.py` is Python. CI runs `python3 -m unittest scripts/test_fetch_weights.py` and `python3 scripts/verify_docs.py` (`.github/workflows/ci.yml`).

## Zero-drift rule

A commit that adds, moves, renames, or changes files, public APIs, MLX layers, or `Package.swift` constraints must update `docs/knowledge-graph.json`, `docs/knowledge-graph.md`, and the affected `docs/wiki/*.md` in the same commit. `metadata.verified_commit` stays the commit whose source lines were measured. Explain that in `verified_commit_note` if the docs commit is a different SHA. Run `python3 scripts/verify_docs.py` before pushing.
