# Build, CI, and testing

## Package

`swift-tools-version: 6.2` (`Package.swift:1`). Platforms: macOS 14, iOS 17, visionOS 1 (`Package.swift:6-9`). mlx-swift is `"0.31.3"..<"0.31.5"` (`Package.swift:22`), matching triposr-mlx-swift, because mlx-swift 0.31.5 and later require swift-tools-version 6.3. The lockfile pins 0.31.3 (`Package.resolved:4-11`).

`ShapERuntime` depends on products `MLX` and `MLXNN` and processes `MarchingCubes.metal` (`Package.swift:25-31`).

## Why xcodebuild

`run_tests.sh:1-7` says `swift test` can crash with "Failed to load the default metallib" because MLX's shader library is not bundled. Use Xcode's build so Metal sources compile and `default.metallib` is next to the test runner. CPU `setUp` in tests (for example `Text300MTransformerTests.swift:10-14`) does not remove that requirement.

Scheme name used by this repo: `ShapERuntime-Package` (`run_tests.sh:17-20`, `.github/workflows/ci.yml:42`). `run_tests.sh:18-19` says the autogenerated package scheme is configured for tests and the product scheme is not. These docs were not checked with a local `xcodebuild -list`.

Build:

```bash
xcodebuild build \
  -scheme ShapECLI \
  -destination 'platform=macOS' \
  -skipPackagePluginValidation \
  CODE_SIGNING_ALLOWED=NO
```

Test:

```bash
xcodebuild test \
  -scheme ShapERuntime-Package \
  -destination 'platform=macOS' \
  -skipPackagePluginValidation \
  -parallel-testing-enabled NO \
  CODE_SIGNING_ALLOWED=NO
```

## CI

`.github/workflows/ci.yml` runs on `macos-26` with `DEVELOPER_DIR` set to Xcode 26.6 (`.github/workflows/ci.yml:16-21`). Steps:

- `python3 -m unittest scripts/test_fetch_weights.py`
- `python3 scripts/verify_docs.py`
- `xcodebuild -resolvePackageDependencies` and `xcodebuild -list` (`.github/workflows/ci.yml:37-40`)
- `xcodebuild test -scheme ShapERuntime-Package -destination 'platform=macOS'` with `-skipPackagePluginValidation`, `-skipMacroValidation`, and `CODE_SIGNING_ALLOWED=NO` (`.github/workflows/ci.yml:42-49`)

The workflow does not pass `-parallel-testing-enabled NO`. It does not download the weight bundle. It does not build iOS or visionOS. `.spi.yml` asks the Swift Package Index to try those platforms. That is not this CI job.

## Tests and real weights

`RuntimeBundleFixture` loads `Fixtures/runtime_bundle_stub` from the test bundle (`RuntimeBundleFixture.swift:3-11`). The stub README says it has 28 random tensors and does not prove numerical outputs (`Fixtures/README.md:28-45`).

Tokenizer parity tests skip unless `SHAP_E_BPE` or `SHAP_E_BUNDLE` is set, or `runtime_bundle/bpe_simple_vocab_16e6.txt.gz` exists (`ClipSimpleTokenizerTests.swift:11-36`). For `xcodebuild`, prefix the names with `TEST_RUNNER_` so they are forwarded:

```bash
TEST_RUNNER_SHAP_E_BPE=/path/to/bpe_simple_vocab_16e6.txt.gz \
TEST_RUNNER_SHAP_E_BUNDLE=/path/to/runtime_bundle \
xcodebuild test -scheme ShapERuntime-Package -destination 'platform=macOS' \
  -skipPackagePluginValidation -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO
```

The test file reads `SHAP_E_BPE` and `SHAP_E_BUNDLE`, not the prefixed names.

`README.md:94` records one local macOS run of this scheme: 40 tests, 0 failures, then the three tokenizer tests passed once the vocabulary file was present. That run is not the GitHub Actions log.
